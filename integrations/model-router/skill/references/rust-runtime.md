# Rust 状态运行时（协调器 0.7.x）

在检查运行版本、处理存储故障或切换本机协调器时读取本页。普通派发继续使用统一 `router_dispatch`，公共协议仍为 `runtime_contract_version=2`。

- 认证的 `/health` 中，`version=0.7.x`、`scheduler_backend=rust`、`state_owner=rust`、`scheduler_kernel_alive=true` 才说明新后端正在运行。源码或可执行文件存在不代表已切换。
- Rust 独占状态数据库，Python 保留原生模型适配器和可信文件执行。运行记录写入有版本校验；作业、用量与进度事件一起提交。冲突应重新读取状态和核对证据，不能重放可能已付费或已落盘的操作。
- Rust 状态服务使用配置 `schema_version=2`，阻止旧协调器加载同一配置。不要改回版本 1 来绕过不兼容错误，也不要启动另一工作树中的旧服务访问同一状态库。
- 使用本机注册的 MCP/CLI 入口。Windows 安装入口为 `GlobalTokenTracker/model-router/router.py`，Rust 程序与 GTT 可执行文件同目录；MCP 配置应指向该已安装入口。旧 MCP 连接可继续使用兼容的公共协议，重新连接后加载更新的入口。
- 内核崩溃或通信结果不明时，停止新受理；不会自动启动另一后端。核对原 request_id、运行记录和收据，再在用户授权的维护范围内恢复服务。既有用户授权无需重复索取。
- 手动生成检测按用户明确动作执行，不受后台恢复探针的小时次数上限约束；开关、容量、认证和真实用量记录仍有效。后台恢复探针继续受预算约束。

切换前保留当前开关、模型池、工作流、认证与历史，先确认没有在途操作。部署必须包含匹配的 Python 桥与 Rust 程序。回退同样在空闲窗口明确进行，不能在运行中自动更换状态所有者。

- 0.7.1起通过 `output_steps_v1` 声明自动报告分段；0.7.2补充操作员提示压缩和真实失败用量的效率统计。验证时同时检查特性、实际attempts与最终完整性，不能只看版本号。
