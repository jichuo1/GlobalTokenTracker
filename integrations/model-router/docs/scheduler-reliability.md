# 调度可靠性

正常任务默认允许换源；指定 preferred_route 是偏好。调用方显式 allow_fallback=false 或只给一次尝试仍被尊重，但 plan/submit 返回相应 warnings。Skill 将这种组合限定为有明确目的的单路线诊断，避免普通评审直接使用它。

routing_strategy 默认 auto；quality、speed、reliability、token_efficiency 可表达任务偏好。所有策略先过能力、质量、额度、隔离、截止时间和并发门槛，再排名。可靠性模式更重视近24小时真实生成证据及近期健康；新路线仍可探索。token_efficiency 需要至少三次同任务类型的明确上报用量，并按该类明确用量对应输入规模调整，不混入预算估算，也不推断API价格。研究组负责人/分析用质量偏好、采集用速度、检查用可靠性，仍遵守各角色质量门槛和来源分散。

默认累计预算在成员与互证之外留一次补位余量，仍封顶200000，显式预算不变。仍有尝试次数时，每次执行从剩余总时间中留20%、最多60秒给后续合格来源。次数、总时间、累计预约/估算与明确消耗共同约束重试，不保证每次失败都有足够预算再次生成。研究组每轮没有人工 token 配额，原生限制和组总预算保持原规则。

同类型成功请求保存输入字符移动平均；ETA 根据当前材料相对历史规模线性上调，参考值至少1024字符，无该类历史时采用4096字符。它是保守路由估计，不是延迟承诺。大段逻辑材料另提示拆分或研究组，不自动截断，不改模型思考强度。

## 本轮偏好

用户明确说“这轮优先 ZCode/某模型”，由 Codex对照 inventory 创建独立 scope，并将 scope_id 作为 preference_scope 传入本轮普通任务、研究组和实际子代理 lease。MCP不自行猜测原话或会话边界，也不持久改变全局偏好。每个 source/model/route 精确匹配默认加40分，weight范围0–100，所有硬门槛保持。一个模型可以跨来源匹配；provider偏好用具体 route ID 表达。

router_preferences 的 set 未给scope_id时创建随机作用域；给scope_id时合并更新，未指定字段保留。get读状态，clear显式结束。本轮默认6小时过期，可设60秒至7天；更新默认保留原到期时间。过期/清除后的任务回到中性策略，并在 plan/submit 中显示警告。重启保留未过期偏好，不自动重放任务。

concurrency_bias范围-1到1，负值按全局上限收紧本轮目标，正值提高空闲提供商倾向并增加 recommended_parallel建议。max_parallel为可选1–32目标，最终仍被全局上限收紧。建议只帮助Codex拆分真实独立任务，不自动复制提示词、增加fanout或改变研究组席位。运行中的外部普通/研究组请求及调用方登记的同scope Codex代理共同计数。更新降低上限不取消现有请求，新请求等已有工作结束；饱和scope不会占满普通任务协调队列，也不会通过额外Luna绕过上限。

负责人反馈可促使Codex更新作用域权重；负责人输出本身没有全局配置权限。组席位3–8与5000万/经审批1亿累计预算维持原规则。

示例：先 set `{"preferred_sources":["source-id-from-inventory"],"preferred_models":["model-id-from-inventory"],"weight":60,"max_parallel":2}` 取得scope_id；每个独立问题传 preference_scope。需要同一问题两份独立报告时另设fanout=2。负责人建议收束后，同scope set `{"max_parallel":1}`，原偏好保留；本轮结束clear。下一轮创建新scope或不传scope，避免偏好残留。

认证、额度与模型不可用使路线/相应提供商进入 verification_required 隔离。权重仍随时间衰减，已知不可用状态不会仅因熔断到期解除；小型生成恢复检查或真实成功回报解除对应状态。累计失败记录和任务质量反馈保留。后续不同失败不能覆盖尚未验证的隔离状态。

连续失败达到三次且最近一次是 timeout、provider_request_failed 或 adapter_error 时，具体路线也进入生成验证隔离；既有数据库启动时应用同样门槛。成功回报会清零连续失败计数。普通来源级超时只保留较轻惩罚，不隔离整个应用。明确 native_protocol_mismatch 或 native_configuration_error 则按来源隔离，避免新任务在同一不兼容 CLI 上轮流尝试不同模型。普通选路与精简 inventory 同时识别来源隔离，恢复检查仍共用闲置容量、小时预算和真实生成门槛。

错误识别同时检查原生 result 文本和结构化 errors，避免通用失败摘要遮住额度/认证原因；识别客户端提示的未登录、额度耗尽和未知 CLI 参数。进程 EOF 与 stderr 由不同线程读取，退出时最多等待0.2秒收齐诊断，仍检查取消和期限。公开诊断只增加有界退出码、stderr 长度和枚举超时原因，不输出原生错误正文、命令、认证值或环境。

router_recheck 接收一个现有 route_id，跳过旧熔断等待，不跳过禁用、认证提示、已知额度、共享闲置容量和探针小时预算。只生成固定报告标记，不发送项目代码；失败更新健康，成功证明生成可用。它与后台恢复采用同一计量和取消逻辑，前台任务到来时让出。自动探针在配置超时与历史延迟间取较大的值、最多按120秒历史估计；手动复检至少60秒。原生隐藏用量仍可能事后超出预约，未知值不作为实际消费入账。

明确的 quota_exhausted、insufficient_quota、credit_balance_exhausted 等信号优先于 provider_not_configured 包装；明确429/限流优先于通用认证文字。只有401/403等通用信号时保留认证分类，不推断具体账户余额。

Windows ProcessChannel 经标准库桥接，将原生 CLI 在恢复主线程之前加入 kill-on-close Job；父 CLI 自行退出时也回收所属后代。Unix 清理本次创建的进程组。管道使用分块无缓冲读取，保留逐行JSON边界和2MiB单行限制，避免 BufferedReader 在另一个读线程持锁时阻塞 close。隐藏启动设置保持；取消只影响本次进程树，不影响用户其他客户端。

输入写入由调用线程监控期限，原生进程不读取stdin时仍能退出。文本适配器的输入/EOF共用这条路径；ZCode取消通知是最多0.15秒的尽力发送，已有阻塞写入时跳过。清理先终止所属进程树，再关闭stdin，避免Windows同步WriteFile使关管道本身阻塞。DSH仅做合成夹具回归，不解除实际来源禁用。

离线验证覆盖恢复隔离、瞬时失败不解除隔离、错误优先级、输入规模与期限、显式参数、补位预算、超时后换源、手动复检限额，以及真实进程的父退出/后代回收、无关进程保护、长Unicode输入和隐藏窗口。真实源复检与报告质量需另外验收，不能从这些夹具推出所有模型可用。
