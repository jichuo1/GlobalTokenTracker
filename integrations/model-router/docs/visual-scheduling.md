# 可视定向调度

GTT 的“调度”页分为工作流画布、来源与模型池、调用配置档。布局参考 [Magpie Routing](https://github.com/yetone/magpie#routing-groups) 的集中路由展示及 [ComfyUI 前端](https://github.com/Comfy-Org/ComfyUI_frontend) 的模型库拖拽、节点和连线交互。Windows 使用 Rust、WinUI 和按需重绘 Direct2D，macOS 使用 SwiftUI 与共享 Rust API 客户端、图校验；各平台原生客户端的等待与协议桥接继续由标准库 Python 处理，无新增第三方运行依赖。

## 来源与定向池

扫描读取原生目录，生成检测运行有界探针。界面分别显示未验证、近期生成验证、历史验证过期、冷却和需恢复验证；目录存在与认证提示不等于生成可用。总开关和每来源开关只约束后续派发，已发出调用允许完成并计量。

自动模式沿用能力、质量、配额和期限排名。定向模式仅使用用户放入限时池的路线，按池内顺序选择；池为空或全部到期时停止派发。模型节点还可指定更小的主/备用路线范围，其顺序优先，依然受全局池与来源开关约束。硬池不会自动转为池外模型或 Codex 交接。

## 节点与职责

从画布左侧模型库拖到空白创建模型节点，拖到节点框替换绑定。移动节点调整位置，连接输出与下游输入声明依赖；“按顺序串联”将节点顺序变为依赖链。就绪节点按保存顺序分配，独立分支可在共享容量内并行，循环和无效连线被拒绝。未完成绑定的草稿可以保存，执行前必须通过严格校验。

五种节点类型为 model、input、merge、gate、output。11 个模板包括研究、提取、代码评审、逻辑检查、交叉核验、信息支撑、汇总等七类模型职责，以及四类本地节点。职责、标签、提示词和调用参数可修改；本地节点合并证据引用，避免重写大报告。gate 检查上游结构性完成并至少有一份模型报告，不验证语义正确或模型独立性。未知结果与失败阻断下游，完整报告保留在原子作业中，运行索引只给有界摘录与作业引用。

每条工作流单独选择 Luna。关闭后不要求或伪造监工，但预算、并发、质量、来源和恢复隔离保持。普通任务与研究组保留默认真实监工；自动恢复探针仍要求真实监工，手动检测可显式关闭。提交时以稳定 request_id 保证幂等，未知结果不会自动重放；新建相同工作前需明确接受风险。取消不等待原生目录查询，派发前复验取消状态。

## 调用配置档与兼容

inherit、balanced、economy、throughput、deep、compatibility、connectivity 均返回可编辑、可审查的值。配置优先级为：原有服务配置、预设默认值、用户覆盖、节点显式参数；资源上限与原生模型容量共同取较小值。计划返回生效 task 与 policy。协调线程可增减，缩小时不取消在途请求；来源并发同时约束提供商预约和原生槽位。

可配置输出、报告和上下文容量，软/硬截止、首次活动、停滞、排队、重试、fanout、任务/工作流预算、节点数量/职责/输入范围、协议帧与缓冲，以及来源级原生选项、恢复探针频率和小时预算。默认保留旧策略：输出最多524288、普通任务最多4000000 tokens，报告最多4MiB；schema 给出更大的实现范围，提升必须显式设置。目录容量、配置接受与模拟传输通过不代表等量真实生成已验收。

ZCode 支持 prompt/messages 载荷和可选的 requested_options 校验，仍核对提供商、模型和请求的推理级别；额外原生元数据不会原样导出。支持嵌套原生 usage 与常见长度终止值。OpenCode 对照 [服务接口](https://opencode.ai/docs/server/) 和 [1.18.18 提示词执行代码](https://github.com/anomalyco/opencode/blob/v1.18.18/packages/opencode/src/session/prompt.ts)：agent steps、轮询、HTTP 超时、消息页大小可配置，权限读回使用相同生效步数；原生输出环境上限与请求对应。打印式客户端可配置轮数及兼容标志，保留工具禁用和严格 MCP 配置。

原生启动/权限预检能够证明未发出生成时，不记成估算消费；已发出的未知传输结果保留状态与计量，不自动重试相同片段或节点。原始错误正文、凭证和命令不进入公开诊断。设置按 revision 做并发冲突检查并原子替换；外协关闭后拒绝新计划、派发、扫描与生成检测。0.5.0 的认证管理端点保留设置读取/编辑和存量任务的状态、结果、全文分页、列表与取消，便于对账和停止。新提交统一经 [router_dispatch](dispatch-intake.md)，两端原生客户端通过共同的 Rust 调用层转入这一入口，旧工作流计划/提交仅作兼容转发。

## 信息支撑与验收

模型成功返回仍可报告 `information_requests:[{question,reason}]`。运行状态为每个问题分配 `job_id:worker:index` 形式的准确 ID，沿依赖边保留并放入后续模型的 `unresolved_information_requests` 上下文。信息支撑员模板返回 `information_support:[{request_id,summary,evidence}]`，逐项绑定上游问题；无关 ID、缺少证据、重复绑定或超长列表会阻断节点。没有明确支撑的问题继续传播，gate/output 拒绝未解决请求。此检查验证协议与出处绑定，语义证据是否足够仍由人或核验节点判断。

运行中节点只预留其尚未消费的预算，已报告用量不再重复占位；价格未知仍显示未知。状态轮询保留有界索引，完整报告仅在需要时从子作业读取，避免每次进度更新重复写入大报告。

## 画布操作与布局

工作流画布占用窗口剩余空间，模型库、节点参数、输入与结果各自有明确边界。空白处左键拖动平移；也可切换平移工具或使用右/中键。适应按钮按全部节点边界缩放，缩放保持视口中心附近的位置；节点坐标支持 -10000..10000，保存和两端原生校验使用相同范围。参数可清空以继承配置档默认值，打开编辑器不会把缺省值改为非法空字符串。Windows 参数栏独立滚动，运行面板按需展开；macOS 使用可调整分栏、独立图视口和可收起模型库/参数/运行面板。
