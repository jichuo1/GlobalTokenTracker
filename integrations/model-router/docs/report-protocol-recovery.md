# 截断与报告协议恢复

输出截断、报告格式错误、原生传输错误和客户端/常驻服务版本不一致分别处理。失败尝试保留可观测用量；格式兼容不代替证据验收。

## 输出耗尽后的恢复

原生 `length` / `max_tokens` 结束会记录请求上限、可见正文字数，以及原生实际提供的输出/推理计数。原生计数口径可能重叠，不能用相减推断隐藏思考占比。正文为零也可能已经产生费用。

- `adaptive` 遇到明确截断时，在原任务剩余预算、尝试次数、截止时间和路线能力内增加下一次输出目标。下一次实际上限必须高于失败上限；同一明确支持更大输出的路线最多增加一次，否则选择合格替代路线。
- `fixed` 保留调用方显式上限。若某路线的原生上限低于调用方上限，可换到更大容量的路线；已经达到调用方上限时停止，避免反复用同一不足上限生成。小于32768的固定逻辑任务会返回 `logical_fixed_output_below_reasoning_default` 提示。
- `native` 采用明确的原生容量；发生截断后不会用相同已耗尽容量重放。没有满足恢复下限的路线时返回 `output_recovery_unavailable`。
- 足够大的切片产生非空或可见长度未知的截断正文时，交给已有缩片机制。明确正文为零时先处理输出余量，不把它当成材料边界错误。恢复下限/目标随切片保存；总预算和未知付费结果的恢复规则保持原有约束。

所有失败和补位分别记账，预约在退出时释放。临时预约占用仍等待释放；永久预算不足不会通过提高输出上限或另起任务绕过。

## 有界格式兼容

最终报告允许完整JSON对象、单个JSON代码围栏，以及不超过1000字符的简单外围说明。解析器仅移除这些确定的包装，仍要求 `summary`、三个报告数组和严格的 `complete=true`。

0.3.1增加显式report_max_chars：默认120000，最多4194304字符，统一控制提示词报告长度、严格解析和原生帧容量。基础协议2保持兼容，health另声明report_capacity_v1；新字段在旧服务派发前被明确拒绝。大报告的collect仍有界裁剪，完整报告保留私有状态库，不把回收裁剪当成生成截断。

截断JSON、多个文档、重复键、非有限数值、无效Unicode和包含另一个JSON结构的歧义包装均被拒绝。不会补括号、编造完成标志或通过另一轮模型生成改写证据。网页任务继续要求真实工具观测来源。

负责人反馈中的 `worker` 仍表示当前结果的整数slot。兼容精确的数字字符串和 `slot 1` 形式，规范化后检查范围及重复投票；角色名和报告ID不会被猜测为slot。负责人上下文提供本轮 `feedback_targets`，明确区分slot与报告worker。

公开错误只含错误码、有限原因枚举和长度/偏移计数。相关失败的最终正文最多留8000字符脱敏摘录于本机尝试工作区 `report-contract-diagnostic.json`，用于定位协议偏差；该文件不进入公开结果、事件或仓库。没有返回正文的失败也不会从隐藏推理或提示词构造诊断正文。

## 原生帧与运行版本

原生子进程继续要求逐行JSON对象帧。单帧预算按已批准的有效输出容量调整，至少2MiB、最多16MiB；接收队列按帧预算收紧，排队帧容量约束在64MiB以内。OpenCode快照沿用相同容量约束，研究组保留16MiB上限。这个上限用于原生结果、用量及状态包装，最终报告仍单独有界。

0.3.0常驻服务的认证 `/health` 返回 `version` 和 `runtime_contract_version=2`。客户端在计划、提交、续研、合组及手动生成检查前核对协议版本；不一致时返回 `resident_protocol_mismatch`，不发出任务，也不自动重启共享服务。旧服务的查询、取消和已有结果回收仍可执行。

OpenCode工作进程显式设置批准的OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX；1.18.18标准请求参数由该运行参数与模型原生上限决定，agent options不是标准输出上限的替代。代理步骤界限调整为2，避免首次请求即触发原生最后一步总结指令；工具权限和调用后工具检查保留。来源依据为[对应版本请求构造](https://github.com/anomalyco/opencode/blob/v1.18.18/packages/opencode/src/session/llm/request.ts)及[步骤限制说明](https://opencode.ai/docs/agents/#max-steps)。

终态保存最新的真实活动快照，保留既有native阶段信息；快照刷新不会伪造活动或延长租约。普通任务显式queue_wait_s优先于legacy短接力默认，未显式指定时沿原配置；容量和总截止仍是硬约束。

0.3.2将EOF处不完整JSON单独标为incomplete_output/incomplete_json，并保留原生stop/length等finish reason；stop不能证明正文完整，也不能被改称原生length。活动按每个worker的最新attempt冻结，组中其他任务继续执行时完成者不再增长idle。切片/角色/错误码/计量来源随尝试事件提供；信息交付闭合单独发事件并保留精确问题ID，答案正确性仍待核验。

纯活动状态约30秒采样，阶段、预约、计量、失败及问题变化立即发出；监督进度以实时快照为准。超过回收容量的单事件保留原event_id和显式省略标识并前进cursor，完整原记录仍在本机日志。聚合任务允许32报告/8问题，所有报告摘录共享14000字符；未知/未完成报告引用仍拒绝。修复协议后可复用已保存的负责人决策继续聚合，保留原费用、完成切片和问题门槛。

缓存任务在重启后续跑时，研究组执行入口先加载路线目录，避免绕过规划后对空目录误报无可用路线。明确EOF不完整JSON且正文非空的大切片交回缩片队列，保留incomplete_output及原生stop原因，失败计量与子片分别记录；缺完成标志等其他协议错误仍沿原换源路径。研究组提取允许最多16条finding，要求分组保留全部所请求记录；通用4条finding约束不能成为丢弃记录的理由。

角色消息超过600字符时明确给出summary_excerpt_only、原长度及full_message_event，原事件保留完整消息；发送成功不代表模型收到了全文。每个已结束attempt的活动冻结时间优先于后续组结束时间，组继续复核或交给调用方不会重新增加完成者的静默年龄。

负责人已指定报告引用的任务去掉无关的最近报告上下文，避免将其他范围案例混入当前证据。切片明确标注supplied_context_complete_for_range与offset_unit=python_characters：源范围完整、引用报告可能是摘录、偏移为字符而非字节；字段完整不代表单片包含整条跨片记录，边界与结论仍需独立核验。

长报告摘录将摘要与正文分开，正文预算不再重复序列化摘要；已保存findings不因摘要前缀再次占满同一预算而完全不可见。摘录仍可能省略后续证据，保持excerpt_only及完整报告定位，不能把这一优化当作全报告投递。

continue_research的顶层information_request_ids只有在完整等于next_tasks各项精确绑定ID的并集时才可规范化去除；最多8个且必须唯一，不能有额外/缺失ID或用于其他动作。原报告保留原字段，规范化决策不赋予隐含关闭问题的含义；各任务和未解决问题门槛继续核对。

提取/摘要的已报告历史用量明显以输出为主、且当前输入估算加有效输出上限明显更小时，ETA按这个有界工作量修正，最低仍取历史耗时的四分之一；不把长输出耗时再按短任务输入比例无限放大。未知/估算用量、大输出及逻辑审查保留原估计，实际排队、硬截止、质量、预算与恢复隔离门槛不变，ETA继续只是估计。

仅有native_phase时，真实启动阶段计入观察，但不能把较长的首次响应窗缩成idle+grace；正文、推理或真实工具响应出现后，继续沿空闲规则处理停滞。重复阶段、心跳和空帧仍不续期，整个等待始终受硬截止约束。阶段信号不证明已经产生模型正文。

OpenCode未完成消息中的全零tokens是启动占位，不能证明真实零消耗；有正计数时保留观察值，没有可靠计数的超时按预约保守估算。恢复旧的opencode原生消息超时reported=0记录时幂等补记估算，原零值留usage_placeholder，原去重ID与账单记录键保持，不重复生成或增加一份账单。估算是未知消耗的调度预留，不是供应商实际费用。used与尚未释放的完整预约在计量转换短窗可能重复覆盖同一次尝试，不能将短暂相加直接称为实际超支；清理后核对实际记录与预约零值。

恢复计量后达到组预算时进入group_budget_exhausted审批入口，保留未知结果门禁，不让调用方被困在无法申请扩展的旧状态。报告引用视图保留范围/哈希，去除任务开始时复制的过期state；完整源记录不修改，报告是否已结束依实际结果判断。

升级时需要同时核对仓库、实际MCP入口的安装副本、常驻进程和安装的Skill。只更新源码或只刷新工具列表不能证明新调度已在线。先回收正在执行的任务、备份将被替换的代码，保留私有配置/状态/认证，再在允许的维护窗口切换常驻服务并刷新客户端。

## 验证边界

`test_report_protocol` 覆盖完整包装兼容、歧义/部分报告拒绝、反馈slot规范化、来源证据门槛、私有内容不进入公开错误、真实子进程对象帧/大帧限制，以及旧运行版本的派发前拒绝。`test_truncation_recovery` 覆盖输出增加、固定上限、跨路线补位、剩余总预算裁剪、双次计费及研究组零正文恢复。

测试使用合成原生帧、隔离状态与适配器，不代表每个模型支持目录公布的最大输出，也不代表共享安装已切换。全套结果见[验证范围](verification.md)。
