# 操作员与回报拓扑验收（2026-10-24）

## 实现范围

0.6.0 增加真实 caller Codex 母节点、operator、reviewer、task/report 两平面和完整拓扑控制。母节点不是自动完成的 input，也不是软件冒充的 Codex；调用方明确返回分配、具体修正批准与证据验收。原生模型继续只返回结构化操作，本地可信执行器实际修改明确授权的文件。

文件/材料切片、父子授权、并行文件冲突、报告来源、实际前后文件与 diff、独立审阅及最终文件复核均连接到统一 dispatch。操作进度持久投递，回报不能自己授权写入；不同工作版本的事件不相互去重。估算 tokens 是 tokens_used 的子集，本地操作不重复计模型消费。

## 离线与文件回归

专项覆盖真实临时文件写入与唯一替换、原子替换前取消、同文件并发冲突、Windows 实际 junction 越界拒绝、已批准固定命令的输出与进程树取消、未知命令防重放，以及跨重启复用已验证报告后仅重做已知未落盘操作。

工作流回归包含：多级两个操作员 → 第三模型审阅 → 母节点批准局部修正 → 只重跑对应节点 → 再审和最终验收；两个独立负评不能因修正一个而被清除；同正文不同审阅者的 proposal 身份不混淆；修正不能扩大父级授权；审阅仅从真实 after_files 判断，验收前外部改文件会拒绝；信息请求按准确 ID 闭合。

双向操作员回报不阻塞初次派发；仅报告输入的审阅者不会提前运行。task/report 各自无环之外，还检查有效启动前置，拒绝审阅者等待自身任务后代的不可启动组合。Rust 预览与 Python 执行校验保持同一规则。

行分片回归验证 `[start_line,end_line]` 的精确替换保留文件其他部分，片段不能 write_text 成全文，子级行范围不能扩大父级，大材料会要求继续切片。Windows 测试明确固定样例换行，实际执行保留原文件的真实换行与全文件哈希。

## Windows 界面观察

通过 Computer Use 的官方 sky 工具打开独立 GTT_DATA_DIR、FakeCatalog/fake adapter 实例，正式服务未参与写入或生成。实际截图确认蓝色任务线、琥珀回报线、不同端口/方向、任务/回报/双向菜单，以及缺少精确工作区授权时的运行阻断。

首次截图发现源节点低于目标时回报长对角线穿卡片，已修为共用的正交外侧绕行，并补 9 组方向/窄间隙几何回归与短末段箭头约束。唯一母节点后添加时现在移到 task 链首，保留 report。用户按物理 Escape 后立即停止所有窗口控制，没有再次点击或截图。

因此没有修复后截图、真实指针拖拽连线验收或 macOS 运行验收。Mac 已同步编解码、异色线、母节点/操作员/审阅者、授权及状态，Windows 环境没有 Swift 编译器。独立界面与 Fake 后端保留供用户自行关闭；其进程身份在 GTT target/diagnostics/operator-visual-*/processes.json，不能误作正式进程。

## 有界原生模型负载

隔离实例仅授权 example.py，目标由当前真实 Codex 查看完整拓扑后下发：将 VALUE = 1 改为 VALUE = 2，保留末尾换行。总测试预算 48,000，禁止后台恢复和自动换源，正式调度开关与配置保持。

| 尝试 | 结果与证据 |
|---|---|
| DeepSeek Flash 第一条路线 | 8,192 输出 tokens 全为原生思考，无正文，length 截断；明确消费 8,975，未修改文件、未启动审阅 |
| 另一条 DeepSeek Flash 路线 | provider_request_failed；保留 17,609 估算消费，未修改文件，不解除或掩盖故障 |
| Gemini Flash 首轮 | 返回完整且基线正确的 replace_text，但 sources 中用文件名，被原网页 URL 校验拒绝；明确消费 8,389，保留原失败。已补仅限 operator 授权快照的文件来源规范化，普通/网页来源规则不放宽 |
| Gemini Flash 最后一次 | 完整原生报告通过，明确消费 12,065；首次实际操作被独立测试池到期阻断，基线与文件仍未变 |

当前 Codex 核对已验证报告与实际未变文件，明确更新独立实例的选定池并批准 retry_operations。执行器复用原付费报告，新的原始文件基线检查通过后实际落盘，**没有再次生成**。跨重启的完成顺序与证据核对也经过本次现场检查并修复：旧失败快照不能覆盖较新的实际执行快照。

最终文件实际为 VALUE = 2，AST 仅含这一赋值，完整 SHA 与 applied 收据和 after_files 一致；由当前 Codex 绑定最终 evidence_digest 接受。四次原生尝试保守累计 **47,038 tokens**，其中 **29,429 明确上报、17,609 为包含其中的估算**；预约归零，重做文件步骤没有增加模型作业。

现场两条 DeepSeek 路线未通过，也没有完成另一真实模型的最终审阅；第三方审阅、反馈与局部修正通过的是模型夹具加真实文件回归。不能据此声称 DeepSeek 当前可稳定承接或已经证明速度提升。原始证据、全部失败、提案复用与实际验收保留在协调器 diagnostics/operator-live-*/final-verification.json 及相关报告，未抹去失败记录。
