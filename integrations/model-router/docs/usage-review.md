# 协作用量回流验证

本次修复给协调器增加独立、脱敏的 `usage_records` 表。与任务状态同事务保存，重复保存不变更水位，字段补全时沿稳定调用键推进全局水位。原生请求身份用于跨渠道去重；恢复探测使用 UUID，避免数据库更换后计数 ID 重复。

仅保存模型、提供商标识、软件、时间、状态、计量方式与 token 数值。提示词、上下文、报告、API 配置、原始错误正文均不进入该表。消费者只读该表；明确上报、调度估算、原生日志计量分开处理。

审查包含外部有界 review 和主线源码核对。外部调用达到尝试上限后回退 Luna。后续 review 找到 OpenCode 工具拒绝和模型不匹配路径丢失已返回用量，已修复，并补上失败路径断言。

验证：Python 105 项测试通过。GTT 全工作区 237 项测试通过、3 项既有测试忽略；Clippy 通过。SQLite 副本中 19 条历史记录补账后再次扫描新增 0 条；缺少维度的总量保持未分类、未定价。生成后的格式失败、原生部分记录补全、游标与写入失败回滚、重启重放均有回归测试。

计量契约及 GTT 接入说明见公开仓库 `docs/COORDINATION_USAGE.md`。旧版本恢复记录只保留预算计数，未记录上报/估算标志，因此不强行补成实际消费；新版恢复检查保存完整计量方式。

部署后的补充核对：恢复检查记录请求开始时间与实际耗时，避免跨午夜的请求按完成时间归到错误日期。新真实调用的用量持久化后已被 GTT 自动监听入账，重扫维持一笔；双官方 MCP 客户端的共享服务与 10 工具协议验证通过。

补充 review 还找到恢复检查提前取消时跳过异常携带用量的问题，已将计量提取移到取消处理之前。新增正数/零上报取消回归后，Python 106 项通过；真实调用返回 544 tokens，GTT 自动入账一笔。
