# 输出预算扩展

普通任务显式输出上限现为524288 tokens，计入模型思考和正文。小材料逻辑任务仍从32768 tokens / 600秒开始；检索、提取、整理从8192 / 180开始。未指定输出上限时按材料规模计算adaptive预算；显式max_output_tokens默认fixed，原生输出上限和上下文余量仍会收紧。

未指定总预算时，根据输入长度、指令开销、并发成员和验证轮次留出空间，按8192对齐；常规默认封顶200000，显式超过65536输出或native模式可扩大，普通任务硬上限4000000。显式总预算优先。预算临时被其他请求预约时等待释放；首选路线预算过大时继续检查其他合格路线。真实计量优先，未知用量单独标估算。

研究组默认adaptive按切片规模计算每次生成预算；output_mode=native显式采用模型报告的完整输出上限，未知上限使用有限自适应预算。512000原生上限不会被普通任务原来的65536限制截断。它表示允许请求的余量，不要求生成这么多tokens，也不要求增加最终报告篇幅。框架仍保留有界报告、管道单帧和协议容量限制。

原生模型的正整数输出上限用于实际请求和预约计算，并公开 requested_output_tokens / effective_output_tokens。OpenCode 使用其模型目录的 limit.output；ZCode 按配置原生顺序解析模型、API、站点、模板和精确覆写的 optionSpecs.maxOutputTokens.max，不能把上下文窗口当输出上限。

历史真实ZCode校验曾拒绝65536：错误为“outside the model option range”，发生在模型请求发出前。补齐范围识别后，32000原生上限路线按32000执行。此历史证据证明范围识别；本次更大的预算范围由回归验证，不把目录容量当作512k实际输出测试。

此前117项基线/输出预算回归和真实Step短生成验证了原生范围、显式小预算、预约及真实计量。本次扩展另外覆盖524288显式边界、512000原生预算、上下文余量、动态切片与等待释放；测试夹具不代表512k真实生成验收。
